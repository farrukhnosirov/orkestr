# ADR-0006: TypeScript types generated from Rust with ts-rs

- **Status:** Accepted
- **Date:** 2026-10-02
- **Phase:** 1
- **Spec:** §47, §60.1, §60.4, §65 #19, §67
- **Review:** CA-7, CA-8
- **Spike:** SP-14 · **Risk:** R-17

## Context

The protocol's source of truth is Rust: `orkestr-protocol` and the entities in `orkestr-domain`. Three TS clients consume it: desktop, web and mobile. Hand-written TS types drift, and drift shows up only at runtime.

## Decision drivers

1. Single source of truth in Rust; TS compile errors appear when the protocol changes.
2. No extra IDL toolchain on Windows.
3. Generated output is reviewable in diffs (stable, deterministic ordering).
4. Faithful serde semantics: `rename_all`, `tag`/`content`, `Option`, `skip_serializing_if`.

## Considered options

| Option | Verdict |
|---|---|
| **ts-rs (derive `TS`, export with `cargo test`)** | **Chosen**. Mature, honours serde attributes, per-type files |
| specta / tauri-specta | Rejected. Ties type export to Tauri commands, and most of our types are not Tauri commands (ADR-0005) |
| typeshare (1Password) | Viable, but needs a separate CLI binary and has weaker support for complex enums (adjacently tagged) |
| JSON Schema (schemars) → json-schema-to-typescript | Kept only for **UI config** validation (ADR-0015), where a runtime schema is needed anyway. Too lossy and verbose for the whole protocol |
| Hand-written TS | Rejected (drift) |

## Decision

- `orkestr-protocol` and `orkestr-domain` (behind feature `ts`, CA-7) derive `ts_rs::TS` on every wire type with `#[ts(export)]`.
- **Generation:**
  - Run `cargo test -p orkestr-protocol export_bindings`, with `TS_RS_EXPORT_DIR=packages/protocol/src/generated` set in `.cargo/config.toml` `[env]` (`relative = true`).
  - ts-rs features: `serde-compat`, `uuid-impl`, `chrono-impl`, `serde-json-impl`, `no-serde-warnings`.
- **Numbers (CA-8):**
  - ts-rs maps `u64`/`i64` to `bigint`, but JSON gives `number`. Every 64-bit integer on the wire is annotated `#[ts(type = "number")]` and must stay below `Number.MAX_SAFE_INTEGER`. That holds for seq, rev, token counts, byte sizes and cents.
  - Money is `i64` micro-dollars (`costMicros`), never floats.
  - A unit test in `orkestr-protocol` scans the generated `.ts` files and fails if the word `bigint` appears.
- **IDs:** newtypes (ADR-0020) export as `export type ProjectId = string;`.
- **Methods map:**
  - `packages/protocol/src/index.ts` (integrator-owned) re-exports `generated/*` and declares `export interface Methods { "projects.list": [ProjectsListParams, ProjectsListResult]; … }`.
  - To prevent drift, `orkestr-protocol` also exports `METHODS: &[(&str, &str, &str)]` (method, params type, result type). A test compares it against the `Methods` keys parsed from `index.ts`.
- **Generated files are committed.** CI runs the export and then `git diff --exit-code packages/protocol/src/generated`. Stale bindings fail the build.
- **Event union:** `EventKind` uses `#[serde(tag = "kind", content = "payload")]`, which exports a discriminated union `{ kind: "TaskCreated"; payload: TaskCreatedPayload } | …`. `Event` flattens it (`#[serde(flatten)]`), and ts-rs supports flatten on a struct whose field is an enum. If flatten turns out to be unsupported for adjacently tagged enums in the pinned ts-rs version (SP-14 verifies this), the envelope becomes `{…, kind, payload}` with an explicit `#[ts(type = "…")]` override generated by a small build test.

Example:

```rust
#[derive(Serialize, Deserialize, TS)]
#[serde(rename_all = "camelCase")]
#[ts(export)]
pub struct TasksTransitionParams {
    pub task_id: TaskId,
    pub to: TaskStatus,
    #[serde(default, skip_serializing_if = "Option::is_none")]
    #[ts(optional)]
    pub reason: Option<String>,
    #[ts(type = "number")]
    pub expected_rev: u64,
}
```

## Consequences

- **Positive:** protocol changes break the TS build right away; there is no IDL; Web and Mobile get the types for free.
- **Negative:** generation runs through `cargo test`, which is a little unusual. It is documented in `CONTRIBUTING` and the `npm run gen:protocol` script.
- **Negative:** generic types and some serde features (`untagged` with complex content) export poorly. Rule: the protocol uses **no** `untagged` enums and no generic wire types beyond `Page<T>`, which is exported as concrete aliases.

## Implementation notes (Phase 0 foundation, 2026-10-02)

Status and errata only; the decision above is unchanged.

- ts-rs **12** with features `serde-compat`, `chrono-impl`, `uuid-impl`, `serde-json-impl` (no `no-serde-warnings`).
- `orkestr-domain` derives `TS` **unconditionally** (no `ts` feature); CA-7 is resolved that way. `ts-rs` adds no I/O to the domain crate.
- **64-bit integers:** instead of per-field `#[ts(type = "number")]`, `.cargo/config.toml` sets `TS_RS_LARGE_INT = "number"`, so every `u64`/`i64` exports as `number`. The `bigint` scan test is not written; the generated files contain no `bigint` today.
- **Money** is `f64` USD on the wire (`costUsd`, `maxCostUsd`, `spentUsd`), not `i64` micro-dollars; integer micro-USD remains the planned *storage* representation (`../architecture/data-model.md` §1.1).
- **Methods map:** generated, not hand-written: `export_bindings` writes `generated/methods.ts` (`Methods`, `METHOD_NAMES`, `PROTOCOL_VERSION`, `EVENT_KINDS`, `UI_CONFIG_SCHEMA_VERSION`) from `orkestr_protocol::methods::registry()`; `packages/protocol/src/index.ts` re-exports it and adds `MethodName`/`ParamsOf`/`ResultOf`. A core test (`router_covers_protocol_registry_exactly`) replaces the planned `METHODS` comparison.
- **Flatten works:** `Event` exports as `{ seq, id, ts, projectId, …, correlationId } & ({ kind: "ProjectCreated", payload: ProjectPayload } | …)` and narrows on `kind` (SP-14 question answered).
- Regeneration: `npm run gen:protocol` (`scripts/gen-protocol.mjs`) clears the directory, runs the export and writes the `generated/index.ts` barrel. There is no CI drift check yet (no CI).
